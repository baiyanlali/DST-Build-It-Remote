# 2026-09-04

## DST mod「量子建造 / Build It From Chest」bug 定位与修复（v1.3.16 → v1.3.17）

**玩家反馈**：1) 造物时有概率不消耗原材料；2) 使用卡顿。

**参考源码**：``（本地解包的最新 DST 脚本）

### 定位到的根因

1. **`Inventory:Has` 覆盖无条件生效** —— 原版有一批系统用 `Has(prefab, n)`（两参数、非合成语境）做门槛检查，扣除却只认自己身上的物品：`wortox_soul`（灵魂跳跃/上限）、`rope_bridge`、`pumpkincarvable`、`snowmandecoratable`、`pigman` 代币、`itemaffinity`。mod 把箱子算进去后 → 检查通过、效果生效、材料一个没扣。**这是"不消耗原材料"的主因。**
2. **缓存内的箱子不做 `IsValid()` 校验** —— `cache_chests` TTL = REFRESH_TIME（默认 5s）。箱子被烧/拆后，Lua 表仍被缓存引用，`v.prefab` / `stackable.stacksize` 照样可读 → 幽灵材料 → 白嫖合成。
3. **`RemoveItem` 覆盖是死代码（v1.3.16 引入的回归）** —— 原版 `Inventory:RemoveItem`（inventory.lua:1453）和 `Container:RemoveItem`（container.lua:1015）找不到物品时都 `return item`，**永不返回 nil**。所以 `if return_item ~= nil then return return_item end` 恒真，后面遍历箱子的整段从未执行。目前"能扣"纯靠 `stackable:Get()` 分裂 + `InventoryItem:OnRemoveEntity`（inventoryitem.lua:478）兜底的巧合。
4. **`GetCraftingIngredient` 用 `crafting_items[k] = v` 覆盖式写入** —— 会顶掉原版已算好的条目，同时 `total_num_found` 重复累加 → 取料不齐。
5. **客户端双重计数** —— `Inventory_Replica` 没有 `opencontainers` 字段（只有 `GetOpenContainers()`），原代码 `local opencontainers = self.opencontainers` 恒为 nil → 已打开的箱子被算两遍（实测 6+4 报成 16）。主机模式下 replica 转发给权威组件后又叠一次。
6. **`net_string` 溢出 + 展开礼物包裹** —— `net_string` 长度有限，装满的箱子字符串会被截断；且 `UpdateContainerAll` 把 `unwrappable.itemdata` 内的物品也算进客户端可用材料，而服务端 `Container:Has` 完全看不到包裹内物品 → 口径不一致。
7. **卡顿主因** —— (a) `Has` 每次调用都 `遍历箱子 × 遍历槽位`，而合成菜单每次 `refreshcrafting` 会对上千配方逐材料调 `Has`；(b) `UpdateContainerAll` 挂在 `itemget/itemlose/stacksizechange` 上无节流，合成扣料每扣 1 个就全量重建字符串 + 广播。
8. `local ThePlayer = _G.ThePlayer` 在 modmain 顶层取值恒为 nil → `inst == ThePlayer` 恒假 → 那个 `DoPeriodicTask(1.0, refreshcrafting)` 其实从未创建（歪打正着）。
9. `function HasInContainers(...)` 漏了 local，污染 `_G`，且无人调用。

### 修复要点（modmain.lua 全量重写，原文件备份为 modmain.lua.bak）

- `Has` / `inventory_replica:Has` 仅在 `checkallcontainers == true` 时扩展。
- 缓存改为**弱键表 + 每玩家时间戳**（去掉全局 DoPeriodicTask 清表，避免所有玩家同帧集体 miss）；取用时校验 `IsValid()`。
- 新增 **`prefab -> 数量` 聚合缓存，TTL 一个 tick**（`GetTime()` 精确相等）→ `Has` 降为 O(1)。实测合成菜单刷新 **47.3ms/帧 → 0.85ms/帧（约 56×）**。
- `RemoveItem` 改为按 `inventoryitem.owner` 定位物品真正所在容器，交给该容器 `RemoveItem`。
- `GetCraftingIngredient` 加 `crafting_items[k] == nil` / `v > 0` / `k:IsValid()` 三重保护。
- `inventory_replica` 用 `GetOpenContainers()`；主机（`inst.components.inventory ~= nil`）直接返回原版结果。
- `container_replica:Has` 在有权威数据或箱子已打开（有 classified）时走原版，只有未打开才用广播近似值。
- 容器同步：**同帧合并（DoTaskInTime(0)）+ 内容未变不发送 + 长度上限 240 字节 + 去掉 unwrappable 展开**。
- `refreshcrafting` 周期任务改为 REFRESH_TIME 间隔，且只在 `HUD:IsCraftingOpen()` 时才推。

### 追加：v1.3.17 上线即闪退（modmain.lua:110）已修复

**现象**：客户端建房/进档在 `Loading modmain.lua` 处直接崩，日志：
`modmain.lua:110: attempt to call global 'setmetatable' (a nil value)`，随后 main.lua 加载失败、`Failed mSimulation->Reset()`、1 秒内退出；其后 plantregistry/json/`SetGlobalErrorWidget` 一串报错均为连带污染，非独立问题。

**根因（重要约束，改本 mod 必须遵守）**：DST 的 mod 沙箱 `CreateEnvironment`（scripts/mods.lua）是**纯白名单表**，只注入 pairs/ipairs/print/math/table/type/string/tostring/require/Class/TUNING/GLOBAL 等，**不含 `setmetatable`/`getmetatable`/`tonumber` 等标准库全局，也无 __index 回退**。上一轮重写引入的弱键缓存 `local cache = setmetatable({}, {__mode="k"})` 裸调了未本地化的 setmetatable → 加载即崩。

**修复**：改为 `_G.setmetatable({}, {__mode="k"})`（modmain.lua:112）。经验法则：modmain 顶层任何非白名单全局（setmetatable、tonumber、GetTime、TheSim 等）都必须 `_G.xxx` 或先 `local x = _G.xxx`。
