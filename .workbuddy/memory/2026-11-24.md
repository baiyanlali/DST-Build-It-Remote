## v1.3.21 修复快捷栏（固定栏）制造「有概率不消耗材料」

**现象**：白炎反馈快捷栏制造存在不消耗材料的情况。

**根因**（对照本地 `data/databundles/scripts.zip` 里原版 builder.lua / inventory.lua / widgetutil.lua 静态审查 + harness 复现）：
1. 原版 Builder 把「检查」与「扣料」拆成两步，且**不校验取料数量**：`HasIngredients -> MakeRecipe/BufferBuild -> DoBuild -> GetIngredients -> RemoveIngredients -> 生成产物`。`Has` 说够而 `GetCraftingIngredient` 取不齐时，产物照造、材料少扣或不扣。建筑配方走 `BufferBuild` 预扣一次后 `DoBuild` 永久跳过扣料；快捷栏长按连造放大该窗口。
2. mod 的 `Has`/`GetSurroundingCounts` 用 `pairs(container.slots)` 统计，取料却调 `Container:GetCraftingIngredient`（只遍历 `1..numslots`）→ 稀疏/扩展槽「算得出、取不到」。
3. `GetSurroundingCounts` 的按 tick 聚合缓存只在合成取料/扣料时失效；同一 tick 内箱子内容被外部改动（其他玩家、烧毁、腐坏）时缓存陈旧 → `HasIngredients` 误报够料。

**修复**（modmain.lua）：
- 新增 `BuildCraftingIngredients`：与 `GetSurroundingCounts` 同源的 `pairs(slots)` + `Count()` + `IsValid/nocrafting` 过滤；`GetCraftingIngredient` 与 `VerifyTakeable` 共用，保证检查与扣料同源。
- `Has` 在 `num_found >= amount`（即将允许制造）时用 `VerifyTakeable` 复核实际可取总量，不足直接拒绝；不够的配方仍走 O(1) 快速路径。
- 引入全局 `container_revision`：任何容器内容变化（RemoveItem 扣料、GetCraftingIngredient、服务端 `DoUpdateContainer` 结果变化、客户端 `OnContainerDirty`）都 +1；counts/verify 缓存按 (tick, revision, prefab) 失效，兼顾实时性与性能。
- 客户端 `inventory_replica:Has` 在够料分支用实时快照复核，避免广播晚一帧导致「客户端说够、服务端拒造」的空点。
- 版本 1.3.21，modinfo.lua 补更新日志。

**测试**：harness.lua 新增 Q1–Q6（连续制造守恒、缓存脱节、槽位口径差、打开容器混合、BufferBuild 语义、Has/取料一致）。全套 harness 34 + client 6 + sync_refresh 12 全绿；bench 1.35ms/帧 → 2.65ms/帧（复核带来的增量，仍远优于旧版 47ms）。
